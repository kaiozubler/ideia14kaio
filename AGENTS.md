# Architecture decisions

- Read `docs/architecture-rules.md` before changes; it preserves the existing signature, protocol, clinic and document invariants.
- Agent integrations use OAuth-protected read-only MCP tools in `src/lib/mcp/` and forward verified caller tokens to RLS, because external assistants must preserve clinic permissions.
- MCP consent uses a dedicated public login callback with a validated same-origin return path, because the legacy static entry cannot preserve an authorization request.
- Browser-local MCP registrations remain in their owning React screens and cannot approve consent, because authorization requires a human decision.
- The Zubler CRM manages clinics, users, access and payments only through `/api/public/crm/*`, authenticated by `Authorization: Bearer <CRM_BRIDGE_TOKEN>` compared in constant time before `supabaseAdmin` is loaded, and every write is logged in `crm_auditoria` (service_role only) with the `X-CRM-Actor` header, because the CRM is a separate app holding a service-level secret.
- Suspended access lives in `acessos_bloqueados`; blocking a clinic blocks its owner and every `clinica_membros` login, and also bans them in Supabase Auth, because the app reads the database directly and a still-open session would otherwise keep refreshing its token. The app checks `acesso_bloqueado(uid)` on every load and login, and the global request middleware in `src/start.ts` answers 403 `acesso_suspenso` on any `/api/*` for a blocked JWT `sub` (read unverified, since it is only used to deny).
- `pagamentos_manuais` rows are never deleted (a trigger rejects DELETE); a refund only sets `status = 'estornado'`, and a confirmed manual payment moves an `inadimplente` subscription back to `ativa`, because the CRM's payment history must stay reconcilable. Asaas recurring charges are recorded in `asaas_cobrancas` by the webhook so the CRM sees both origins in one list.
